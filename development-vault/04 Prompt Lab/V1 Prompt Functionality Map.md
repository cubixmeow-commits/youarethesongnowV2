# V1 Prompt Functionality Map

This note is the working-vault map of the recoverable Arcana V1 prompt system.

## The important finding

V1 did not have one prompt. Prompt behavior came from five different places:

1. **Source-static** — hardcoded PHP templates/directives.
2. **Runtime-assembled** — PHP compiled Song DNA, portraits, options, style and policy into the image prompt.
3. **Database-stored** — later static visual styles lived in `arcana_styles.prompt_text` and could be edited through the admin style manager.
4. **Model-generated** — Song DNA, Band Visual DNA and StyleMap were generated by text-model stages.
5. **Fallback mutations** — retry attempts rewrote/simplified the image request after failures.

## Functional pipeline

```text
Artist + Song + Lyrics
        ↓
Song DNA analysis
        ↓
12-field structured interpretation
        ↓
Base cinematic prompt compiler
        ├─ portrait role
        ├─ custom instructions
        ├─ aspect / technical rules
        └─ safety / branding
        ↓
Style path
        ├─ none
        ├─ DB static style
        └─ Band Visual DNA → StyleMap
        ↓
Image provider
        ↓
7-step retry / safety mutations
```

## Database prompt note

The final V1 design definitely stored static style prompt text in the database. The admin handler exposes CRUD for:

- `style_key`
- `name`
- `prompt_text`
- `category`
- `sample_image_url`
- `is_active`
- `sort_order`

The newer worker loads `arcana_styles.prompt_text` for the selected style.

The repository does **not** prove every final production DB row without a database export, but the older `arcana.queue.processor.php` preserves a very large inline style catalog that appears to be a strong predecessor to the database-managed version.

## Legacy style catalog

The inline catalog contains dozens of presets across:

- cinematic / photoreal;
- painting / ink / collage;
- cyberpunk / sci-fi / fantasy;
- vaporwave / synthwave;
- punk / grunge / hip-hop;
- jazz / gothic / dreamcore;
- era/genre hybrids from the 1920s through 2020s;
- special dynamic album-art and historical-performance analysis modes.

These are valuable research material, not code we need to copy verbatim.

## Strong behaviors to preserve

- understand the song before asking for pixels;
- structured Song DNA;
- make uploaded people protagonists rather than passive references;
- concrete cinematography language;
- soft user steering;
- curated + dynamic visual identity;
- controlled fallback rather than immediate failure.

## Weak behavior to redesign

- mega-prompt conflicts;
- exact portrait match vs “no recognizable real people”;
- branding vs “no text”;
- silent portrait removal on retries;
- mutable DB prompts without revision history;
- multiple worker variants as competing prompt truth;
- old model-specific hacks.
