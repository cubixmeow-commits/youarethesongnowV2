Headline distinction: “Dynamic Band Lore Engine™” is marketing for the overall pipeline. In code, lore is not a separate subsystem — Song DNA interprets the song, and Dynamic Band Style is an optional visual-style generator.

ENGINE COMPONENTS

Cards from the forensic prompt audit.

Song DNA

summary, narrative, themes, symbols, mood, metaphors, palette, lighting, camera, composition, influences, texture.

Dynamic Band Style

Album-cover visual DNA → StyleMap headings (STYLE/MEDIUM/COLOR/…). Ignores lyrics and Song DNA.

Prompt Compiler

PHP assembles a long ordered prompt: mission → DNA → character → cinematography → tech → safety → custom → style.

Portrait Integration

One or two refs become protagonists with exact facial-match instructions — until retries drop them.

Retry Chain

Attempts 1–3 keep portraits; attempt 4 removes them; 6–7 go abstract/landscape on IMAGE_SAFETY.

Major Weaknesses

Lore/style naming gap, branding vs no-text, silent identity loss, lyric persistence, mega-prompt overload.

Strongest V1 Ideas

Staged DNA, portrait-as-protagonist, soft custom rules, async jobs, StyleMap-as-design-brief.

V2 Opportunities

Visual Narrative Plan, separate artist identity, identity-preserving retries, honest lore-or-style product language.

WHAT WE LEARNED FROM THE ACTUAL PROMPTS

High-value findings without reading every Markdown file.

  1. Song DNA is real and always on — a 12-field JSON blueprint, not a vague slogan.
  2. “Dynamic Band Lore” ≠ a lore system — implementation is interpretation + optional visual StyleMap.
  3. Default UI never triggers StyleMap — empty image_style skips the whole style block.
  4. StyleMap ignores lyrics — it uses band + song title and album-cover knowledge only.
  5. “Cinematic” is concrete craft language — depth, motivated light, motion, filmic materials — not just adjectives.
  6. Portraits conflict with safety text — exact face match vs “no recognizable real people.”
  7. Identity dies at attempt 4 — retries preserve mood longer than the user’s face.
  8. Branding fights “no text” — same prompt demands and forbids visible captions.
  9. Full lyrics persist in DB even though analysis is told not to quote them.
  10. One giant prompt does too many jobs — V2 should compile from intermediate artifacts.

PRESERVE THE IDEA

What looks worth carrying forward.

  • Song interpretation before image generation
  • Explicit Song DNA as a domain artifact
  • Artist/band visual identity as its own brief
  • Portrait-reference creation mode
  • Durable async generation jobs
  • Personal project/gallery history
  • Progressive retry — reordered to protect identity
LEAVE THE LEGACY BEHIND

What should not be copied blindly.

  • Multiple overlapping PHP worker scripts
  • Marketing “lore” without a lore subsystem
  • Silent portrait dropping on success
  • Contradictory branding / no-text prompts
  • Hardwired Gemini model versions
  • Full lyric persistence by default
  • One mega-prompt doing every creative job
